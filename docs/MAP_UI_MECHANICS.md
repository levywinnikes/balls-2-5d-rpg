# Map UI Mechanics

## Goal

The map UI must remain readable, predictable, and consistent with the canonical world coordinates used by the runtime and `PlayerState`.

## Canonical Rule

- The world buffer generated by `WorldMapService` is the source of truth.
- No component may mirror X or Y independently.
- All player, marker, and context-menu coordinates must be derived from the helpers in `src/ui/utils/MapCoordinateUtils.ts`.
- `PlayerState` stores canonical world position only (world pixels = grid * 32).
- Axis convention: `+X = east = right on screen`, `+Y = south = down on screen`. The 3D runtime publishes `(player.position.x * 32, player.position.z * 32)` to match this. Any axis inversion observed in-game must be fixed at its source (3D camera/input), never by mirroring in UI components.

## Minimap Model (HUD — sidebar)

- **Player-centered**: the player marker is fixed at the canvas center.
- The world buffer is drawn shifted so the player's world position lands at the canvas center.
- 1 grid tile = `MAP_UI_BUFFER_TILE_SIZE * zoom` pixels in the canvas.
- Fog of war is drawn only over tiles inside the visible region around the player (perf + consistency with player-centered framing).
- Right-click adds a marker at the world position under the cursor, computed by inverting the player-centered transform: `gridX = playerGridX + (mouseX - centerX) / tilePx`.
- North is up, south is down — same orientation as the 3D scene seen from above.

## World Map Model (expanded window)

- **World-locked**: the level buffer is drawn pixel-perfect (1 buffer pixel = 4 px per tile, then CSS-scaled by `zoom`). The user pans by drag and zooms with the wheel.
- The player marker is drawn on the buffer at the canonical grid position and **scales inversely with zoom** so it stays ~6 px visually at any zoom level (white square + black outline + red center).
- Markers and the right-click cursor use the same `worldToGridPoint` / `gridToBufferPx` helpers.
- **Persistence (UX)**: zoom and per-level scroll position are persisted in module scope (`persistedView` in `ExpandedMapWindow.tsx`). Closing and reopening the map restores the previous framing per floor. First open auto-centers on the player.

## UX Rules

- Prefer icon-first controls and a quiet frame.
- Keep direction consistent with the world, not with ad-hoc screen flips.
- Use strong contrast for the hero marker and markers, but avoid visual clutter.
- Preserve pixel clarity by avoiding image smoothing on the map canvas.
- Markers drawn on the expanded map must remain visible at low zoom (scale inversely with zoom).

## Maintenance Rules

- If the map behavior changes, update this document and `docs/MECHANICS_DELTAS.md` in the same task.
- Do not introduce per-component axis compensation. Fix axis bugs at the source (3D runtime).
- Do not duplicate world/grid conversion formulas inside UI components — extend `MapCoordinateUtils.ts` instead.
